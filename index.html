Ez
Billing

Billing software that doesn’t wear out the person using it. A full retail billing and inventory system, built with two other students.

  • Python
  • Tkinter
  • MySQL

Generic billing tires out the people who use it all day.

Cluttered screens slow cashiers down and cause mistakes at the counter. My goal was to cut the clutter and shorten the path of a sale to four steps.

  1. Search product
  2. Set quantity
  3. Apply coupon
  4. Finalize sale

Try one: a list

Problem: too much scrolling for the tasks done most.

Fix: a fixed layout that never scrolls mid-sale.

Try two: everything

Problem: too many buttons at once overloaded people.

Fix: only the 5 core actions up front, the rest in sub-menus.

Try three: search only

Problem: clean, but typing for every item is slow.

Fix: big touch targets, so you tap instead of type.

From sketch to system

Wireframes first, then the same layout built as real screens.

Built for mistakes

Anything destructive asks first. Records for customers, products and employees sit in one system, with a three-column entry layout that cuts scanning time.

It works, end to end

The Tkinter front end talks to a MySQL back end, so what you see is a working system, not a mock-up. The biggest lesson: good structure behind the screen is what makes the screen feel simple.

My part

In a team of three, I designed the interface and user flow, wrote the MySQL database layer, and connected the Tkinter front end to it.
